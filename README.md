# 留白 Spacewell · 本地磁盘管理

中文本地可视化工作台：查看 C / D / E / F 容量、逐层查找大文件、预览清理与迁移操作，并恢复已转移文件。使用 Python 标准库，无需安装第三方依赖。

## 启动可视化界面

双击 `start.cmd`，浏览器会打开 `http://127.0.0.1:8765`。保持启动窗口运行，关闭窗口会停止服务。只监听本机回环地址，不对局域网或互联网开放，不上传磁盘数据。

```powershell
python app.py
# 端口被其他程序占用时可更改端口
python app.py --port 8766
```

### 文件操作规则

- 文件转移必须先预览，再确认；预览有效期 10 分钟。每次最多 50,000 个文件。
- 只操作当前用户下载、桌面、文档、图片、视频、音乐及已识别模型和缓存目录。系统 / 应用目录、数据库、虚拟磁盘、代码状态、云占位、联接点等由系统或应用专项管理。
- 缓存目录中包含最近 7 天修改的文件时，整目录转移会停止；可在空间分析中逐项选择旧文件。
- 清理区 `目标盘/Spacewell-Recovery/操作ID/` 和迁移区 `目标盘/Spacewell-Migrated/操作ID/` 都建立独立目标，不覆盖原有数据。**清理区是跨盘保留副本的清理，释放源盘空间但不减少所有磁盘总占用。** 永久删除需在资源管理器自行核对处理，之后无法恢复。
- Windows 使用原生 CopyFileExW 保留文件属性、时间及 NTFS 数据流（含下载来源标记）；复制后校验主要文件内容的 SHA-256，再核验源文件未变化，最后移除源文件。日志在移除前落盘。参考 [Microsoft CopyFileExW](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-copyfileexw)。
- 取消在当前文件校验完成后生效。中断或失败可能留下部分完成结果和目标副本，不会宣称全量完成。已转移文件可从操作记录恢复；变化的文件或同名冲突不覆盖。
- 源空目录保留，不自动切换软件配置、系统文件夹位置或创建联接点。迁移模型后需自行设置模型路径。关闭使用源文件的应用后再执行；本工具不是在线数据库/虚拟机迁移工具。
- `local-state` 保存恢复日志，请保留；目标文件被修改或删除后可能无法自动恢复。恢复同样需要源盘空间。
- 服务运行期间会监听当前扫描范围内的文件变化，通常几秒内更新目录大小、文件数量和大文件列表；只检查变化的目录，新增子目录会单独扫描。磁盘剩余容量约每 10 秒刷新，回到页面时也会刷新。大量变化可能需要更久；监听不可用时页面会提示，可手动重新扫描。
- 扫描单个文件夹时，首页展示该文件夹的空间构成和大文件，其他磁盘折叠为参考信息。每行“定位”和详情中的“在资源管理器中选中”会打开父目录并选中目标，无需手动搜索。
- 自动更新不会覆盖历史扫描快照。文件移入回收站后会从原目录统计中消失，但通常需要从回收站永久删除后才释放对应磁盘空间。
- 本机接口检查 Host / Origin 和每次启动的会话令牌；仅固定静态资源可访问，没有任意 shell 命令接口。按启动用户的权限运行，不自动提权。

## 只读命令行扫描

安装有 Python 3.10 或更新版本时，双击 `scan.cmd`：扫描所有固定磁盘，完成后打开中文离线报告。扫描可能需要几分钟；控制台每约 10 秒显示进度。可按 Ctrl+C 中断（中断扫描不产生完整报告）。

也可在本项目目录运行：

```powershell
# 仅 C 盘
python storage_audit.py

# 全部固定磁盘
python storage_audit.py --all

# 针对某个目录快速复查
python storage_audit.py --roots "C:\Users\YourName\.codex"

# 与历史快照比较（将文件名替换为实际快照；两次扫描范围须一致）
python storage_audit.py --all --compare "reports\scan-YYYYMMDD-HHMMSS-ffffff.json"

# 运行校验
python -m unittest -v
```

## 产物

- `reports/latest.html`：最近一次扫描的报告。双击即可打开，支持按磁盘和路径筛选。
- `reports/report-*.html`：每次扫描的独立报告。
- `reports/scan-*.json`：全部目录统计、大文件、建议、错误计数及前 300 条错误样例。命令行默认保存最大的 200 个文件，可视化界面新扫描保存最大的 2,000 个。
- HTML 为保持响应速度，只嵌入最大的 3,000 个目录，每个视图显示前 200 个匹配项。JSON 不截断目录。
- 所有文件保存在项目目录内，报告目录自动排除扫描；`.gitignore` 排除报告以避免误上传个人路径。

## 如何理解结果

1. **可用容量**来自操作系统；目录大小是可读取文件的逻辑字节总和，两者不是相同指标。
2. 硬链接可能重复计数；压缩和稀疏文件逻辑大小可能远大于实际占用。父目录包含子目录，不能累加排名或建议中的大小。
3. 链接、目录联接、云占位和离线文件跳过，避免跨盘重复扫描或触发下载。无权限、占用或扫描期间消失的文件记录为未统计项，并向上汇总“不完整”状态。
4. 扫描不提权，不改变权限，不读取文件内容；只访问路径、大小、修改时间等元数据。它不是一致性文件系统快照，运行中的应用仍可能改变文件。
5. 清理建议是基于已知路径的候选，不保证其中每个文件可删。30 天未修改不代表无用，未知类型默认人工核对。
6. 首次扫描不能证明磁盘增长由某次安装引起。后续同范围快照可比较两次都完整读取的同名目录；新增/消失目录的变化可体现在其完整父目录中。
7. 命令行 `storage_audit.py` 保持只读；可视化 `app.py` 中经确认的文件转移会移除源文件，但保留目标副本及恢复日志。

## 处理顺序

先核对已知缓存和 Windows 存储设置中的临时文件，再考虑下载、视频、数据集等个人资料。迁移时先复制、核验，再切换软件保存路径；源数据的删除是最后一步。目标盘还需要确认长期连接、备份策略及剩余空间，盘符本身不能证明它是内置盘。

不要手动清空 `Windows`、`WinSxS`、`Installer`、`Program Files`、`ProgramData`、`AppData` 或 `.codex`。软件安装目录应通过软件自身机制、Windows 应用管理或重新安装更改位置。

Codex 官方说明状态默认位于 `CODEX_HOME`（通常 `~/.codex`），其中包含配置、认证等持久数据。这不等于 Windows 桌面版所有数据均可通过一个环境变量完整迁移。工作树可按官方文档通过 Settings → Worktrees → Worktree root 指定新位置，但应先核对当前应用界面和现有工作区。不要直接删除带未提交代码的工作树。

官方资料（核对于 2026-10-09）：

- [Codex 配置和状态位置](https://learn.chatgpt.com/docs/config-file/config-advanced)
- [工作树管理与清理](https://learn.chatgpt.com/docs/environments/git-worktrees)

报告包含本机文件路径，分享前需要脱敏。历史报告会占用 E 盘空间，可按需保留最近几次。

### 批量移入回收站

文件列表支持逐项勾选、全选当前页和取消选择。点击“移入回收站”，核对项目、完整路径及总大小后确认即可。每批最多 100 项，选中文件夹会包含全部内容；父子路径自动去重。系统和应用状态等受保护数据不支持此操作。预览后变化的项目会跳过，结束后显示逐项错误并更新统计。回收站文件通过 Windows 回收站恢复，操作结果另存于 local-state/recycle-*.json。
